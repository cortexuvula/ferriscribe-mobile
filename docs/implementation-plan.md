# FerriScribe Mobile — Implementation Plan

## Phase 0 — Scaffold & pairing (P0)

- Flutter project init (iOS + Android), Tailscale reachability to the server.
- `flutter_secure_storage` for tokens/keys; `sqlcipher_flutter_libs` (pin `^2.1.0`) + `drift` for the local cache.
- Android `FLAG_SECURE` + iOS screen-capture protection + **app-switcher snapshot masking** (blur overlay on `AppLifecycleState.inactive`).
- **Backup exclusion:** iOS `NSURLIsExcludedFromBackupKey` on the app data dir; Android `android:allowBackup="false"` + extraction rules.
- Pairing flow (QR → token exchange) against a running office-server; short-lived session tokens with refresh.
- No Sentry/Crashlytics/Firebase integrated.

**Acceptance:** app pairs to a running office-server; token persists securely across restarts; app-switcher shows blur not content; backup excludes app data.

## Phase 1 — Record + ingest (P1) ⚠️ depends on server-side delta

> **Critical path dependency:** the server must have `/recordings`, `/jobs/{id}` endpoints live before this phase can be verified end-to-end. The parallel server track must deliver first.

- Microphone capture (`record`), **streaming AES-256-GCM encryption** — audio chunks flow directly into the encryptor, never touching disk as plaintext. Use `cryptography` package with streaming or a platform channel to native `CommonCrypto`/`javax.crypto.Cipher` for large files (a 30-min WAV can be ~300MB; pure-Dart AES will be too slow).
- Upload (`POST /recordings`), job-status SSE (`GET /jobs/{id}`). SSE handling: manual line-splitting with reconnect logic, or the `sse_client` package.
- Server runs whisper.cpp + the existing pipeline (stages: `Transcription → IcdCoding → DemographicsExtraction → PatientMatching → ClinicalValidation → RagIndexing → Complete`), then document generation (5 doc types). Mobile renders progress for both phases.
- SSE constraint: event payloads carry IDs only, no PHI.

**Acceptance:** record a consultation on the phone → a SOAP note appears, generated by the local server. Temp-dir scan after recording session shows zero plaintext audio files.

## Phase 2 — Five doc types + review/edit

- Fetch documents (`GET /recordings/{id}/documents`).
- Editors for `soap | referral | letter | synopsis | peer_discussion`.
- Save edits back (`PUT /recordings/{id}/documents/{type}`).
- Clipboard: explicit user-initiated copies only, never auto-copy.

**Acceptance:** view and edit all 5 doc types on-device; edits persist to the server.

## Phase 3 — Export + share

- Export via `POST /recordings/{id}/export` (server-side `medical-export`), download.
- System share sheet for the resulting PDF/DOCX.

**Acceptance:** export a SOAP note to PDF and share it from the phone.

## Phase 4 — Offline + polish

- Offline read cache (SQLCipher) of fetched documents.
- Patient context capture; error/retry UX; empty/loading states.
- Token refresh flow; unpair from server.

**Acceptance:** previously fetched documents are viewable with the server unreachable.

## Parallel track — server-side delta (CRITICAL PATH)

Extend `medical-sharing`'s paired HTTP API with **net-new endpoints**:

1. **Recording ingestion** — `POST /recordings` to receive encrypted audio blob, store, and enqueue.
2. **Job queue + status** — job tracking system, `GET /jobs/{id}` SSE stream covering both ingestion pipeline stages and document generation progress.
3. **Document read/write** — `GET /recordings/{id}/documents`, `PUT /recordings/{id}/documents/{type}`.
4. **Export** — `POST /recordings/{id}/export` invoking `medical-export`.
5. **Unpair** — `DELETE /devices/{device_id}` for device revocation.

Reuse the existing pipeline, providers, and `medical-export` crate. No new inference code.

SSE constraint: event payloads carry IDs only — no patient names or transcript content.
