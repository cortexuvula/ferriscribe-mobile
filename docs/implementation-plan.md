# FerriScribe Mobile — Implementation Plan

## Phase 0 — Scaffold & pairing (P0)

- Flutter project init (iOS + Android), Tailscale reachability to the server.
- `flutter_secure_storage` for tokens/keys; `sqlcipher_flutter_libs` + `drift` for the local cache.
- Android `FLAG_SECURE` via platform channel (set before first frame) + iOS `UIScreen.isCaptured`/app-switcher protection (platform channel — budget time, it's not a one-liner).
- Verify `sqlcipher_flutter_libs` ships an arm64-simulator slice (M-series sim link failure otherwise); dev fallback `sqlite3_flutter_libs` behind a compile flag.
- Wire `drift` codegen (`build_runner`) into a Make/script target; generated `.g.dart` files are not hand-editable.
- Pairing flow (QR → token exchange) against a running office-server.

**Acceptance:** app pairs to a running office-server; token persists securely across restarts.

## Phase 1 — Record + ingest (P1)

- Microphone capture (`record`), **chunked** AES-GCM encryption streamed from the recorder (64 KB chunks — never whole-blob).
- Mic permissions: iOS `NSMicrophoneUsageDescription` in `Info.plist`; Android `RECORD_AUDIO` in the manifest + runtime request. (A missing plist string is an App Store rejection, not a build error.)
- Decide audio format: WAV (16 kHz mono — whisper-native, larger files) vs AAC/Opus (smaller, needs server ffmpeg transcode).
- Upload (`POST /recordings`) with **background upload + resume** (iOS `NSURLSession` background sessions; Android `WorkManager`/foreground service) — a recording must never be silently lost when the app backgrounds.
- job-status SSE (`GET /jobs/{id}` with `last_event_id` replay).
- Server runs whisper.cpp + the existing pipeline; mobile renders progress.
- Retention: delete local audio after confirmed server acknowledgment; add a storage-usage indicator.

**Acceptance:** record a consultation on the phone → a SOAP note appears, generated by the local server.

## Phase 2 — Five doc types + review/edit

- Fetch documents (`GET /recordings/{id}/documents`).
- Editors for `soap | referral | letter | synopsis | peer_discussion`.
- Save edits back (`PUT /recordings/{id}/documents/{type}`).
- Write fetched documents to the SQLCipher cache at fetch time (local persistence from day one).

**Acceptance:** view and edit all 5 doc types on-device; edits persist to the server; fetched docs are cached locally.

## Phase 3 — Export + share

- Export via `POST /recordings/{id}/export` (server-side `medical-export`), download.
- System share sheet for the resulting PDF/DOCX.

**Acceptance:** export a SOAP note to PDF and share it from the phone.

## Phase 4 — Offline + polish

- Read-when-offline UI: empty/loading states, sync indicators, retry (cache writes already ship in Phase 2).
- Patient context capture; notifications; error/retry UX.

**Acceptance:** previously fetched documents are viewable with the server unreachable.

## Parallel track — server-side delta

Extend `medical-sharing`'s paired HTTP API with: audio ingest, job-status SSE, document read/write, and export. Reuse the existing pipeline and `medical-export`; no new inference code.

## Verification (both sides)

- Flutter: `flutter analyze` clean, `flutter test` green, `dart format --output=none --set-exit-if-changed .` clean.
- Server (Rust, if touched): `cargo test --workspace --lib`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`.
- PHI gate: no PHI in logs on either side; audio/DB encrypted at rest; no cloud endpoint contacted.
